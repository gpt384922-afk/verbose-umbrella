# Дизайн Выбора Префиксов И Preflight Проверки IP

## Цель

Упростить запуск ханта: вместо ручного ввода пользователь выбирает префиксы из заранее заданного списка. Перед финальным подтверждением бот проверяет выбранные аккаунты и организации на уже существующие публичные IP из известных префиксов и показывает предупреждение прямо на экране с кнопкой `Запустить`.

## Выбранный Подход

Используем фиксированный список известных префиксов в коде приложения:

- `158.160` — для всех операторов;
- `84.201` — для всех операторов;
- `51.250` — только для Мегафон;
- `87.250.247-254` — для всех операторов;
- `77.88.21` — для всех операторов.

Этот список используется в двух местах:

- интерфейс запуска ханта показывает его как кнопочный мультивыбор;
- backend защищает уже существующие IP из любого известного префикса от удаления, даже если этот префикс не выбран целью текущего ханта.

## Интерфейс Запуска Ханта

Текущий поток остается тем же по смыслу:

1. Выбор аккаунтов.
2. Выбор организаций.
3. Выбор префиксов.
4. Выбор количества IP на каждое облако.
5. Проверка и запуск.

Шаг `Префиксы` меняется с ручного текстового ввода на inline-кнопки. Пользователь может выбрать один или несколько префиксов. На экране видны описания:

- `158.160`, `84.201`, `87.250.247-254` и `77.88.21`: для всех операторов;
- `51.250`: только для Мегафон.

Кнопка `Дальше` доступна в том же экране. Если пользователь не выбрал ни одного префикса, бот показывает короткую ошибку и остается на шаге выбора.

## Preflight Проверка

После выбора цели, перед показом финального подтверждения, scheduler выполняет read-only проверку выбранных scope:

1. Для каждого выбранного аккаунта открывает YC client в рамках branch scope.
2. Для каждой выбранной организации получает список облаков.
3. Для каждого активного облака получает список папок через read-only `list_folders`.
4. Для каждой найденной папки получает публичные VPC addresses.
5. Фильтрует IP по всем известным префиксам: `158.160`, `84.201`, `51.250`, `87.250.247-254`, `77.88.21`.

Preflight не создает папки, не создает IP, не меняет billing и не удаляет ресурсы. Если в облаке нет папок, оно просто пропускается для проверки адресов.

Финальный экран подтверждения показывает результат preflight отдельным блоком перед кнопкой `Запустить`. Для каждого найденного IP указываем IP, префикс, аккаунт, организацию и короткий cloud id. Если найденных IP нет, показываем строку `Существующие IP из известных префиксов не найдены`.

## Поведение При Запуске Ханта

Выбранные пользователем префиксы остаются единственными целями ханта. Новые IP засчитываются как результат только если они подходят под выбранный список.

Уже существующие IP из любого известного префикса обрабатываются отдельно:

- их облака не удаляются при подготовке или замене облаков;
- такие IP не считаются успешной находкой текущего ханта, если их префикс не выбран пользователем;
- пользователь заранее видит их на экране подтверждения;
- в логах остается событие, что облако пропущено из-за существующего известного префикса.

Пример: пользователь выбрал `84.201` и `51.250`, но preflight нашел `158.160.10.20`. Бот показывает предупреждение, запускает хант только по `84.201` и `51.250`, а облако и сам айпи `158.160.10.20` не удаляет.

## Архитектура

Добавляем модуль `ycbot/core/prefixes.py` для известных префиксов, чтобы UI, scheduler и hunter не дублировали строки.

В `handlers.py`:

- вместо message handler для ручного ввода префиксов добавляется callback flow для мультивыбора;
- финальный экран получает `preflight_existing_ips` из FSM data и добавляет блок предупреждений в `_hunt_confirm_text`.

В `keyboards.py`:

- добавляется клавиатура выбора префиксов;
- кнопка `Назад` возвращает к организациям, `Отмена` работает как раньше.

В `scheduler.py`:

- добавляется метод read-only preflight scan для выбранных `HuntStartScope`;
- метод проверяет branch ownership так же, как остальные операции scheduler;
- ошибки отдельных scope возвращаются в структурированном виде, чтобы пользователь видел, где проверка не прошла.

В `hunter.py`:

- существующая проверка IP перед worker loop использует известные префиксы для защиты облака от удаления;
- проверка match для новых IP продолжает использовать только выбранные префиксы из job state.

## Обработка Ошибок

Если preflight scan не смог проверить часть аккаунтов, бот показывает это на финальном экране отдельной строкой с аккаунтом/организацией и причиной. Запуск не блокируется автоматически, потому что runtime-защита в hunter повторно проверяет известные префиксы перед работой с облаками.

Если пользователь пытается продолжить без выбранных префиксов, бот не переводит его дальше и просит выбрать хотя бы один префикс.

Если на старте ханта `prefixes` пустые или содержат значение не из известного списка, scheduler отклоняет запрос. Это защищает backend от старых FSM-состояний и ручных callback-ошибок.

## Тесты

Добавляем focused tests:

- текст выбора префиксов содержит все три префикса и описания операторов;
- клавиатура выбора префиксов отмечает выбранные значения;
- подтверждение ханта показывает предупреждение о найденных существующих IP;
- scheduler отклоняет неизвестный префикс;
- hunter защищает облако с существующим известным префиксом, даже если этот префикс не выбран целью ханта;
- hunter не засчитывает существующий IP из невыбранного префикса как match текущего ханта.

Ручная проверка:

- выбрать `84.201` и `51.250`;
- убедиться, что финальное подтверждение показывает найденный `158.160`, если он есть на выбранных аккаунтах;
- запустить хант и убедиться, что облако с `158.160` не удаляется, а новые matches засчитываются только для выбранных префиксов.
